# The data package

The data is distributed through the Kaggle competition Data page, not through
this repository. Download it and point the scripts at it with `--release-root`.

## Layout

```text
<release-root>/
  config/
    synthetic_release_v1.json     calendar, scenario contract, Task 2 window policy
    corridors.json                the ten directional corridors
  corridors/<PANEL>/
    network/
      links.csv                   length, lanes, free speed, capacity
      fd_parameters.csv           per-link fundamental-diagram parameters and lane counts
      lwr_mainline_topology.csv   which link feeds which
      ramp_attachment_map.csv     where ramps attach
      path_set.csv                paths, with origin and destination zones
      path_link_incidence.csv     which links each path uses
      base_od.csv                 the weak OD prior
    train/
      mainline_states/year_month=.../     observations, no Task 1 mask
      mainline_states_masked/mask_regime=R1|R2|R3/
                                          the same, with the Task 1 targets blanked
      ramp_states/                        on- and off-ramp flows
    validation/  private/
      mainline_states_masked/mask_regime=R1|R2|R3/
      ramp_states/
  task1/<PANEL>/<split>/sample_submission_state.csv
  task2/<PANEL>/<split>/window_index.csv, window_history.parquet, sample_submission_queue.csv
  task3/<PANEL>/<split>/sample_submission_physics.csv     (schema reference only)
  task4/<PANEL>/<split>/synthetic_link_counts.csv, synthetic_weak_prior.csv,
                        sample_submission_path_flow.csv
```

## Which split has answers

| Split | Masked inputs | Unmasked observations | Use it for |
|---|:--:|:--:|---|
| `train` | yes | **yes** | fitting, and self-scoring your own method |
| `validation` | yes | no | practice submissions |
| `private` | yes | no | the ranked evaluation |

`train` is the only split that ships the unmasked observation layer, so it is
the only split on which you can score yourself for Tasks 1 and 3. Recover the
answer for a blanked cell by joining `mainline_states_masked` to
`mainline_states` on `(timestamp, station_id, link_id)`; `score_task1.py` does
exactly this.

Task 2 is the exception: its queue labels are withheld for every split, train
included, so it cannot be self-scored at all.

## The quality rule

Every mainline and ramp cell carries `pct_observed`, the share of the
five-minute interval a detector actually reported.

```text
is_imputed        = pct_observed < 100
is_score_eligible = pct_observed >= 75 and the required values are non-null
```

Only eligible cells are scored, in every task. Roughly 76% of mainline cells and
76% of ramp cells are eligible, uniformly across the ten corridors. Ineligible
cells are still released — they are part of the problem, not a defect.

An unavailable ramp observation is **unavailable evidence, never a measured zero
flow.** Treating it as zero will cost you Task 3 points, because the evaluator
excludes those transitions rather than assuming the ramp was empty.

## Provenance

The released records are synthetic. They were generated by a calibrated
traffic-flow model whose parameters — free-flow speed, per-lane capacity, jam
density, demand by weekday and time of day, measurement-noise scale, detector
availability — were measured from real freeway detector data on the
corresponding corridors. No real detector record, shifted, resampled or copied,
appears in the release, and the released calendar deliberately does not
correspond to any real period.

The consequence for you: the data obeys real traffic physics and carries
realistic measurement error, but it cannot be looked up. There is no external
source to join against.
